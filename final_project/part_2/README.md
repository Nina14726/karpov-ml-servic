# Вторая часть финального проекта

Персонализированная рекомендательная система для ленты постов.

## Структура

- `schema.py` — Pydantic-модели, перенесённые из первой части проекта.
- `database.py` — функция подключения к PostgreSQL.
- `requirements.txt` — зависимости, разрешённые в окружении LMS.
- `load_data.py` — выгрузка пользователей, постов и просмотров из PostgreSQL.
- `train_model.py` — создание признаков, обучение, оценка и сохранение модели.

## Выгрузка данных

`load_data.py` загружает три датафрейма:

- пользователей из `public.user_data`;
- посты из `public.post_text_df`;
- просмотры из `public.feed_data` с заполненной целевой переменной `target`.

По умолчанию загружается 5 000 000 строк взаимодействий. Допустимый предел задания — 10 000 000 строк.

```bash
python load_data.py
```

Для уменьшенной проверочной выгрузки:

```bash
python load_data.py --feed-limit 10000
```

## Признаки и обучающая выборка

`train_model.py` формирует:

- признаки профиля пользователя;
- признаки темы и текста поста: длину текста, количество слов и количество уникальных слов;
- временные признаки: час, день недели и месяц;
- единую обучающую таблицу с `target`.

Train/test разделяются по времени: более ранние взаимодействия используются для обучения, последние 20% — для проверки.

## Модель и оценка

Используется `CatBoostClassifier`, который поддерживает категориальные признаки. Качество рассчитывается по ROC-AUC отдельно на обучающей и тестовой выборках. Скрипт требует ROC-AUC выше 0.5 на тесте.

После обучения модель сохраняется в `model.pkl` через `pickle`. Затем файл загружается обратно и проверяется наличие методов `predict()` и `predict_proba()`.

Признаки сохраняются в PostgreSQL в таблицы с уникальным префиксом:

- `nina14726_user_features`;
- `nina14726_post_features`.

Запуск полного обучения:

```bash
python train_model.py
```

Проверочный запуск на уменьшенной выборке без записи признаков в БД:

```bash
python train_model.py --feed-limit 10000 --skip-save-features
```
